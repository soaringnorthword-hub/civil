# 挡墙施工台账报检照片登记助手（TzLedger）

把手持「影像资料采集标识牌」或报检单的照片，自动识别成结构化数据，定位到施工台账里对应的挡墙块和部位行，一键写入。用于替代手工翻照片、逐行填 Excel。

Windows 桌面程序，Python + Tkinter，PyInstaller 打包为单文件目录版，Inno Setup 生成安装包。

## 下载安装

**[⬇ 下载 v1.1.1 安装包（74 MB）](https://github.com/soaringnorthword-hub/civil/releases/latest)**

Windows 10 / 11 x64，双击安装，无需 Python 环境。安装包未做代码签名，SmartScreen 提示时选「更多信息 → 仍要运行」。

## 为什么不是"OCR 一把梭"

开发过程中用真实照片实测（全手写标识牌），结论很明确：

| 方案 | 印刷表头 | 手写字段 | 是否可用 |
|---|---|---|---|
| RapidOCR / PP-OCR 轻量模型 | 0.99+ | 0.51~0.79，小数点必丢（1.96→96） | 否 |
| 放大 3 倍 / CLAHE / 锐化 | 无改善 | 无改善 | 否 |
| 视觉大模型（Qwen-VL 等） | 正常 | 可读 | 是 |

所以程序内置两条识别通道，用户可切换：

- **本地离线 OCR**（RapidOCR）：适合微信群文字消息截图、电脑打印的报检单，免密钥、断网可用
- **视觉大模型**（OpenAI 兼容接口）：适合现场手写标识牌，需 API Key

## 核心设计：宁可拒绝，绝不写错

实测发现最危险的缺陷不是"识别不准"，而是"识别错了还能写进台账"。

真实案例：`K28+152.719~K28+162.626` 被 OCR 读成 `K8+152~K128+162`（跨度 120 km），按"最长重叠"的宽松逻辑能匹配到 `K24+712~K24+850` 的某个挡墙块，一按写入就把 K28 的数据塞进 K24 的墙身行，外表完全看不出来。

因此写入前有硬闸门：

| 校验 | 触发动作 |
|---|---|
| 里程跨度 > 500 m（单个挡墙块只有 4~12 m） | 作废里程，拒绝写入 |
| 顶宽/底宽不在 0.2~8 m | 作废该值（手写小数点丢失） |
| 高度不在 0.05~8 m、方量不在 0.1~500 m³ | 作废该值 |
| 顶宽明显大于底宽 | 标记疑似识别颠倒 |
| 里程不能"唯一完全包含"于某一块 | 不自动定位，列出候选由人工指定 |
| 同一里程存在并行重复段 | 必须人工选择，不猜 |

## 公式保护

台账的 `K/M/Q/U/V/W/X` 列大量是公式（`=K212+J213`、`=J166`、`=IF(S="","",ROUND(S*0.8,0))` 等）。写入时逐格判断，**凡是公式一律跳过**，只填原始数据列，让表格自己联动。

## 模板报验牌的口径

现场标识牌是"模板报验"，牌上只有设计/实测顶宽底宽和报验标高，没有方量和浇筑日期。程序按以下映射写入：

| 台账列 | 来源 |
|---|---|
| O 顶宽 / P 底宽 | 牌上"设计顶宽 / 设计底宽" |
| Q 高 / J 本次浇筑 | 报验标高差（如 `（0-1.5）m` → 1.5） |
| N 施工日期 | 牌上日期 |
| T 浇筑日期 | 留空（模板报验不是浇筑） |
| S 设计方量 | 梯形断面反算 `(顶宽+底宽)/2 × 高 × 块长`（预估值，标注提示） |
| R 强度 | 留空 |

## 目录结构

```
main.py              入口，含崩溃日志与 --selftest 自检
tz/
  parse.py           文本 → 结构化记录，含量纲校验闸门
  ledger.py          台账引擎：扫描挡墙块、严格定位、算值、写入（公式保护）
  vlm.py             视觉大模型客户端（OpenAI 兼容，多服务商预设）
  gui.py             Tkinter 界面
TzLedger.spec        PyInstaller 打包配置
installer.iss        Inno Setup 安装包脚本
使用说明.txt          面向最终用户的操作说明
```

## 从源码运行

```bash
python -m venv venv
venv\Scripts\pip install rapidocr_onnxruntime openpyxl pillow
venv\Scripts\python main.py
```

> 注意：`rapidocr_onnxruntime` 目前不支持 Python 3.13，请用 3.11 / 3.12 建环境。

## 打包

```bash
venv\Scripts\python -m PyInstaller --noconfirm TzLedger.spec
```

再用 Inno Setup 6 编译 `installer.iss` 生成安装包。

## 配置

API Key 等配置存放在 `%APPDATA%\TzLedger\config.json`，**不在仓库内、不随安装包分发**。

## 已知限制

- 手写识别依赖视觉大模型，本地 OCR 对手写无能为力
- 模板报验牌反算的方量与台账设计断面方量可能差 5~15%，需浇筑后按报检单校正
- 写入后 `U/V/W` 列显示 0，需用 Excel/WPS 打开触发重算（openpyxl 不计算公式）
- 台账中存在并行重复段，需人工指定
